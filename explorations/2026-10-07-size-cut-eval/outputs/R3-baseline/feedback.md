**Title:** docs-first route has no reference-only branch; intent pass has no row for an undated, unattributed
status directive

## Category
skill

## What I Observed

1. **Reference-only, docs-first repository.** `entropy-assessment` Step 3 says a reference-only system "may finish
   with a correction or a demotion and no generated guard". But route A hands everything to
   `docs-first-planning-assessment`, and that skill has no lifecycle branch:
   - Step 5's current-state view asks for "active fronts" and "1-3 plausible next actions";
   - Phase 2 assumes a guard is being built or amended.

   In this repository, the costly failure happened when a session started, not at commit. The agent-instructions
   file sent every fresh session to a roadmap and asked it for next actions, despite a reference-only banner. No
   skill names read-time defence as the main remedy, and I had to derive it myself.
2. **Undated, unattributed directive.** The deciding fact was an undated, unattributed status banner in `README.md`
   and `AGENTS.md`. The intent-pass table's "Stale description" row requires "a later recorded steward decision",
   and "Conflict" requires that "no recorded decision settles which wins". Neither fits a directive that has no
   date or author but sits in the instruction file that loads first. I classified the gap through the system's own
   precedence rule, which the table does not mention.
3. **Two guard-surface classifications.** `entropy-assessment`'s Output asks for "Guard surfaces, in the five
   groups of Step 4d". Route A uses docs-first Step 7's keep, amend, replace or demote classification instead. For
   a route-A run, it is unclear which classification the assessment should carry. I gave both in one table.

## Suggestion

- **For 1:** add a short reference-only or frozen branch to `docs-first-planning-assessment` Steps 5 and 9. The
  current-state view becomes a status block with these parts:
  - the stage;
  - where the work moved;
  - what may change;
  - historical material easy to mistake for current;
  - no "next actions" beyond the steward's questions.

  Bootstrap becomes historical labelling at repository scale rather than line-by-line correction. Name the
  start-of-session ritual in the agent-instructions file as the first place to fix, before any commit-time guard.
- **For 2:** in `intent-pass.md` section 3, say how to treat a directive with no attribution or date. One option:
  it counts as recorded intent for staleness when the system's own precedence ranks it above the description. It is
  then recorded into the decision log with its missing attribution visible, and a question is asked only if its
  scope is unclear.
- **For 3:** state in `entropy-assessment`'s Output that route A uses docs-first Step 7's classification, or ask for
  both columns.

## Project Context

A markdown-first architecture blueprint repository with no code, about 75 files. It carries a reference-only banner
naming two successor repositories, plus a decision log, roadmap, component plans, templates and a commit-time guard
generated by an earlier entropy-assessment version (v0.5.2). Its loop is human and AI sessions, with Claude Code and
Pi loading `AGENTS.md`. There is no CI and no hooks. The run was a read-only snapshot evaluation.
